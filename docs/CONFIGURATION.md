# Data contracts and interpretation

Machine-readable structural contracts: [profile v1](../schemas/profile-v1.schema.json), [frame v1](../schemas/frame-v1.schema.json). Runtime codec is authoritative for semantic and byte limits; JSON Schema alone does not enforce cross-profile uniqueness/references or URL credential checks. Gesture definitions inherit the document schema version. Version 0 is explicitly reserved as this prototype's identical-field transitional format; migration changes only its version to 1 after full validation. Unknown/future versions and unknown fields fail closed.

Profiles are <=256 KiB; at most 128 profiles and 128 combined actions+gestures across the whole document. IDs are stable user-data identifiers and must be unique within their defined namespace. Strings have UTF-8 byte/control-character limits. Gesture action references must exist. Extra fields, shell/plugin/code action kinds and downloaded execution payloads are rejected. Pinch, rotate, keyboard shortcuts and showDesktop may be carried as data but are unsupported in this build. Export is semantic round-trip, not a byte-canonical signature format.

Normalized frames carry monotonic seconds, an ephemeral session ID, explicit transport, capabilities and a snapshot of all active contacts plus newly terminal contacts. Completed contacts may disappear from later snapshots; active ones cannot silently disappear. Begin events may assemble for 80ms, up to five contacts. Reusing an active ID with began, introducing a late contact, phase rollback, scope/modifier/capability/transport changes, or a >1s gap during an active sequence cancels it. Idle gaps are harmless. Malformed/out-of-order frames require a known empty boundary. Adapter `confirmEmptyBoundary()` is legal only after all actual contacts have ended/cancelled; it preserves cooldown. It never invents a contact position or pressure value.

Contact-recognition capabilities are always multiTouch + contactIdentity + normalizedCoordinates, plus declared requirements. A profile cannot bypass them by supplying an empty set. Missing pressure/area stay absent. No relation between IOHID discovery metadata and a local AppKit touch device is assumed.

Coordinates start lower-left. Edge zones occupy the outer 20%, corners are intersections; all start-zone checks use the sequence's initial contact centroid. Multi-finger tap/hold use maximum per-contact movement, not final displacement, so out-and-back movement cannot become a tap. Swipe requires coherent translation (maximum per-contact deviation <=0.04 normalized units), minimum travel, and a dominant axis >=1.5 times the other axis. These prototype thresholds are documented, not claimed hardware-tuned. Numerical boundary tolerance is 1e-9. Hold fires on release, default >=0.5s. Tap defaults to <=0.35s; hold/swipe max defaults to 2s.

All eligible candidates survive until release. Winner ordering is application-specific scope, effective capability count, priority descending, stable ID ascending. At most one event is emitted. Cooldown is measured from last completion to next start, per gesture in the current device session. The conflict UI calls the same precedence helper and conservatively identifies overlapping time, zone, modifiers, scope and trigger domains; it does not promise both candidates match every physical input.

Live capture is experimental and expires after 30s. The optional sample export is a separate envelope with source=`appkit-local-unverified`, unknown transport and at most 180 samples over 3s. It contains actual local touch fields only, without app/document/serial identifiers. A fixture must retain that provenance if converted for replay. Repository replay fixtures are explicitly synthetic.


## Experimental local touch samples (separate from profiles)

Sample export schema v2 retains the observed contacts, source `appkit-local-unverified`, unknown transport and unavailable pressure/area. It adds `recording` metadata: optional `armedAt`, `captureStartedAt`, `captureDeadline`, `finishedAt`, `finishReason`, plus `sampleCount`. These are monotonic timestamps from this capture session; `finishedAt` is when stopping was observed, while `captureDeadline` bounds accepted event timestamps. Missing times remain absent, never zero.

The Record 3s button arms a maximum 10-second wait without storing touch frames. A fresh, nonempty all-began frame starts the actual 3-second / 180-frame window. Existing stationary contacts do not begin recording; lift fingers first. Export freezes the sample. Reasons distinguish duration limit, count limit, waiting timeout, explicit export and invalid timestamp. Preview cancellation still clears the bounded buffer; open Export sample before the 30-second preview ends. This change does not enable gesture actions or establish global capture.

Older schema-v1 samples lack these window diagnostics and can still be inspected as historical evidence; sample files are not portable gesture profiles and must not be imported as profiles. Native-interference and full lifecycle context are not encoded in these samples, so replay success alone would not certify native coexistence.
